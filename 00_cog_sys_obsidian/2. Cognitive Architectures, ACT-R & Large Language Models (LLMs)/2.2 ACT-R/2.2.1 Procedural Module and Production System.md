2.2.1 Procedural Module and Production System


The procedural module implements the procedural memory system that manages, matches and executes productions, and coordinates the interactions between all other modules. It has no buffer of its own and coordinates the modules only through their buffers.

- Rules in the production system correspond to procedural knowledge, their conditions correspond to specific states of the modules.
- The production system operates in a critical cycle with a length of **50 ms**: pattern matching of buffer values with production conditions, selection and execution of a matching production, and writing the results back to the corresponding module buffers.
- At every time step the system computes the set of viable production rules; only one production rule can fire per time step.
- If more than one rule matches, a **conflict resolution** mechanism selects the production with the highest utility value, or decides randomly among rules with identical maximum utility.

### Productions

"A production is a statement of a particular contingency that controls behavior. They can be represented as if-then rules" (ACT-R 7 Tutorial).

| Part | Content |
| ---- | ------- |
| Condition | Buffer tests: patterns matched against the current buffer contents, and queries for buffer and module state information |
| Action | Buffer changes and module requests |

### Production syntax

Every production is identified by a name and assembled from a list of buffer operations. Buffer tests and actions are separated by `==>`, and every buffer operation is declared by a header `mbuffername>` where `m` is a modifier determining the operation type.

```
(p ProductionName
   buffer tests
==>
   buffer changes and requests
)
```

| Modifier | Operation |
| -------- | --------- |
| `=buffername>` | Pattern matching in the condition, buffer modification in the action |
| `?buffername>` | Buffer condition query: `buffer <state>` with state full, failure, empty, requested, unrequested; `module <state>` with state free, busy, error |
| `+buffername>` | Buffer request, triggering a module operation; in some situations it implicitly clears the buffer |
| `-buffername>` | Buffer clearing |

Slot values can be constants (`const1`) or variables (`=var1`) that store the value of the matched production; variable names are only defined within their production. A specific slot type can optionally be matched via `ISA`.

### Production utilities

Every production $i$ has a sub-symbolic utility value $U_i$ that can be set manually or learned online:

$$U_i = U_i(n-1) + \alpha\big[R_i(n) - U_i(n-1)\big]$$

with learning rate $\alpha$ and reward $R_i(n)$ for the $n$-th usage of production $i$.

### Production compilation

ACT-R supports the learning of new productions via production compilation:

- the mechanism combines productions that fire in sequence,
- only productions with compatible buffer usage can be combined, and compilation is performed on a buffer-by-buffer basis,
- every buffer has a compilation type specifying when a compilation is valid and how it is performed,
- new productions that are not semantically equivalent to existing ones are added to the procedural memory.
