2.2.3 ACT-R Modeling Examples


Building an ACT-R model always follows the same four steps: define the chunk types, initialize the declarative memory, set the initial goal, and define the production rules.

### Command reference

| Symbol | Meaning |
| ------ | ------- |
| `=goal>` | Read or modify goal buffer |
| `=retrieval>` | Read retrieval buffer |
| `+retrieval>` | Request retrieval from memory |
| `==>` | Action part of production |
| `=x` | Variable binding |
| `ISA` | Chunk type |
| `add-dm` | Store chunk in declarative memory |
| `goal-focus` | Place chunk in goal buffer |

### Example 1: question answering (11 × 3)

Step 1, define a chunk type as a pure data structure, no buffer changes yet:

```
(chunk-type multiplication operand1 operand2 result)
```

Step 2, store the fact in long-term memory:

```
(add-dm
  (mult-11x3 ISA multiplication
     operand1 11
     operand2 3
     result 33))
```

Step 3, put the current task into the goal buffer:

```
(goal-focus
  (g1 ISA goal
     operand1 11
     operand2 3
     state retrieve))
```

Step 4, the first production tests the goal buffer, binds `=x` to 11 and `=y` to 3, sends a retrieval request, and sets the goal state to waiting:

```
(p request-fact
   =goal>
     operand1 =x
     operand2 =y
     state retrieve
==>
   +retrieval>
     ISA multiplication
     operand1 =x
     operand2 =y
   =goal>
     state waiting
)
```

Step 5, the declarative module searches memory, matches `mult-11x3` and places it into the retrieval buffer. Step 6, the second production reads goal and retrieval buffer, binds `=r` to 33 and stores the answer in the goal:

```
(p use-answer
   =goal>
     state waiting
   =retrieval>
     result =r
==>
   =goal>
     state done
     answer =r
)
```

Final workflow: goal buffer "need 11 × 3" → production rule 1 → retrieval request → declarative memory → retrieved chunk result 33 → production rule 2 → goal buffer answer 33. The model has recognized the problem, requested a fact from memory, retrieved it and stored the answer.

### Example 2: counting from num1 to num2

```
(chunk-type count-order first second)
(chunk-type count-from start end count)

(add-dm
  (b ISA count-order first 1 second 2)
  (c ISA count-order first 2 second 3)
  (d ISA count-order first 3 second 4)
  (e ISA count-order first 4 second 5)
  (f ISA count-order first 5 second 6)
  (first-goal ISA count-from start 2 end 4))

(goal-focus first-goal)
```

The start production initializes the counter and requests the successor of the start value, the increment production loops while the count differs from the end value, and the stop production clears the goal buffer once count equals end:

```
(p start                    (P increment                 (P stop
  =goal>                      =goal>                       =goal>
    ISA count-from              ISA count-from               ISA count-from
    start =num1                 count =num1                  count =num
    count nil                   - end =num1                  end =num
==>                             =retrieval>                ==>
  =goal>                          ISA count-order            -goal>
    ISA count-from                first =num1              )
    count =num1                   second =num2
  +retrieval>                 ==>
    ISA count-order             =goal>
    first =num1                   ISA count-from
)                                 count =num2
                                +retrieval>
                                  ISA count-order
                                  first =num2
                              )
```

Note the `- end =num1` test in the increment production: it is a negation, so the rule only fires while the current count is not the end value.

### Practical exercise

The spanning tree algorithm computes shortest paths between a root node $\mathcal{S}$ and any other node of a graph. The corresponding planner is implemented in ACT-R/pyactr (`pip install pyactr`): recall the memory types supported by ACT-R and how memory is addressed, design an ACT-R representation of the graph, and define the productions required to plan from any node to $\mathcal{S}$.
