2.2 ACT-R


Adaptive control of thought-rational (ACT-R) is a hybrid cognitive architecture that implements the principles of a unified theory of cognition. ACT-R is a software framework written in Common Lisp.

- ACT-R is based on **modules**, **buffers** and a **production system**.
- While there is no fixed set of modules, the architecture specifies four main modules for intention, declarative memory, vision and action, plus a procedural module.
- Measurement data from experiments with ACT-R models can be compared to human data.

The modules can be mapped onto brain regions (Möbus et al., 2011): goal, declarative, production, vocal, manual, imaginal, aural and visual, each with its corresponding buffers.

### Modules

Modules represent independent parallel processing units that encapsulate specific functions:

- every module corresponds to one or more cognitive functions of the brain,
- information processing in modules is completely independent and separate from other modules,
- every module can encapsulate arbitrarily complex sub-functions.

| Module | Function |
| ------ | -------- |
| Visual | Visual perception with two buffers representing the dorsal and ventral streams of visual information processing |
| Manual | Simple hand model that can operate a virtual keyboard and a virtual mouse |
| Intentional | Maintains an internal context of intentions for coherent goal-directed behavior; the current goal is exposed via the goal buffer, and the only supported operation is the creation of a new goal chunk |
| Declarative | Storage of chunks comprising the declarative memory |
| Procedural | Manages, matches and executes productions; has no buffer |

### Buffers

Information about the current state of a module is exposed through named buffers. Every buffer stores one chunk and is assigned to exactly one module, serving as interface between modules:

- action requests are submitted through the corresponding module's buffers,
- the chunk stored in a buffer is visible to all other modules,
- buffers directly process queries about their content.

| Query | True if |
| ----- | ------- |
| Empty | There is no chunk in the buffer |
| Full | The buffer contains a chunk |
| Failure | The failure flag is set and the buffer is empty |
| Requested | The chunk in the buffer is the result of a request |
| Unrequested | The chunk in the buffer is not the result of a request |

### Chunks

Declarative knowledge is represented by chunks comprised of **slots**, each storing a single value which can itself be another chunk. Chunks have neither a name nor a type.

```
add84
   addend1 Eight
   addend2 Four
   sum     Twelve
```

### Parallel and serial information processing

| Mode | Where it applies |
| ---- | ---------------- |
| Parallel | Processing within modules can be highly parallel to support high-dimensional data streams (perception of the visual field, parallel search in declarative memory); different modules process data in parallel independently from each other |
| Serial | Every module buffer stores only a single chunk, and in each cycle of the production system exactly one rule fires |

The limitation to a single chunk in every buffer serves as an **attention mechanism**.
