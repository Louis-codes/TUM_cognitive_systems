5.3.1 Underfitting, Overfitting and Validation


The performance of a hypothesis $h \in \mathcal{H}$ is characterized by how well it predicts seen data from the training set and unseen data.

| Term | Meaning |
| ---- | ------- |
| "Fit" | Performance of $h$ on the training data, i.e. the value of $\mathcal{L}$ for $h$ and $\mathcal{S}$ |
| Generalization | Predictive performance of $h$ on data not considered during training |
| Underfitting | $h$ fits the training data poorly and does not model the underlying process because $\mathcal{H}$ is not expressive enough |
| Overfitting | $h$ fits the training data very well but does not model the underlying process because it does not generalize |

Analogy to cognition: an overfitted model learns the data by heart without understanding the underlying rules, like a student who memorizes all exercises of a math book without having understood the theorems.

### Occam's razor

Overfitted models have more parameters than required to capture the properties of the generating process. The law of parsimony states: "Of two competing theories, the simpler explanation of an entity is to be preferred" (Encyclopedia Britannica). In the polynomial fitting example, degree 2 underfits, degrees 7 and 9 overfit, and Occam's razor selects degree 3 over the equally good degrees 4 and 5.

### Detection of overfitting

Overfitting is detected by applying $h$ to unseen samples and computing $\mathcal{L}$. In supervised learning the data is split into three disjoint subsets:

| Subset | Purpose |
| ------ | ------- |
| Training set | Samples used by the learning algorithm to search for $h$ in $\mathcal{H}$ |
| Validation set | Assesses the performance of $h$ after training so that training parameters can be adjusted |
| Test set | Assesses the performance of the final model (samples or real-world data) |

If $h$ is modified based on the performance on the test set, the test set is invalidated.

### Cross-validation

Real-world data is generated by physical processes and therefore limited. **k-fold cross-validation** enables efficient use of data at the cost of computational complexity:

- the dataset is partitioned into $k$ subsets and learned in $k$ iterations,
- in every iteration a different subset serves as validation set,
- the overall performance is the average of the $k$ iterations.

### Avoidance of overfitting

| Method | Idea |
| ------ | ---- |
| Regularization | A regularization term in $\mathcal{L}$ guides learning towards simpler solutions by punishing complexity |
| More training data | Increasing the size and complexity of the dataset reduces overfitting |
| Dataset augmentation | If data is scarce, apply transformations to existing samples (noise, shifts, translations, rotations) |
